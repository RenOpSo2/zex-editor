Static Code Analysis Report - Zex Terminal Editor
==================================================
Analysis Date: 2026-09-01
Analyst: Senior C/C++ Systems Architect & QA Lead
Focus: Memory Safety, Terminal I/O, Edge Cases

CRITICAL BUGS
=============

1. **Severity:** Critical
   **Location:** src/file.cpp:192-194, src/global.h:10, src/editor.c:41-42
   **Bug Description:** Arena capacity (16MB) is smaller than maximum file size limit (64MB). When a file between 16MB-64MB is loaded, it passes the file size check in file_read() but arena_alloc() will start returning NULL during insertion in pgb_insert(). This causes silent data truncation without any error message to the user.
   **Impact:** User loads a large file, editor silently truncates content, user saves partial file thinking it's complete - DATA LOSS. The arena exhaustion is handled silently in pgb_insert() (nodes.c:125-129) by dropping characters.

2. **Severity:** Critical
   **Location:** src/input.c:409-428 (Ctrl+X cut), src/input.c:441-492 (Ctrl+V paste)
   **Bug Description:** Undo/redo system uses fixed-size buffers (MAX_SEARCH_QUERY_LEN = 4096 bytes) to store deleted/inserted text. When cutting or pasting selections larger than 4KB, only the first 4KB is saved for undo. This causes severe data corruption when undoing - only part of the operation is reversed.
   **Impact:** User cuts large selection, pastes elsewhere, tries to undo - only partial undo occurs, leaving document in corrupted state with mixed old/new content. Data integrity violated.

3. **Severity:** Critical
   **Location:** src/input.c:556-562 (backspace handling)
   **Bug Description:** When performing backspace, the code calls pgb_to_str() to extract the character being deleted at position del_pos. However, pgb_to_str() truncates if the buffer exceeds buf_capacity (64KB). If the document is larger than 64KB, the buffer is truncated, and buffer[del_pos] may not contain the actual character at that position. The wrong character is saved for undo.
   **Impact:** Undoing backspace operations on large files (>64KB) inserts the wrong character, corrupting the document. Character at del_pos in truncated buffer differs from actual document.

HIGH SEVERITY BUGS
==================

4. **Severity:** High
   **Location:** src/nodes.c:186-191 (pgb_insert_str)
   **Bug Description:** pgb_insert_str() inserts characters one-by-one in a loop. If the arena becomes exhausted mid-string, some characters are inserted while others are silently dropped. The function has no way to report partial success or failure.
   **Impact:** Text operations (paste, auto-indent, file load) can silently truncate content without user awareness. Document corruption occurs when partial insertions happen.

5. **Severity:** High
   **Location:** src/main.c (no signal handler), src/file.cpp:229-281 (file_write)
   **Bug Description:** No SIGINT (Ctrl+C) signal handler is installed. If user presses Ctrl+C during file write operation, the program terminates immediately. While file_write() uses atomic rename() strategy, if the process dies after fsync() but before rename(), the temp file remains and original file is untouched. However, during file read, Ctrl+C could leave the arena in an inconsistent state.
   **Impact:** User interruption during file operations can leave temporary files, inconsistent editor state, or require manual cleanup. No graceful shutdown.

6. **Severity:** High
   **Location:** src/draw.c:189, src/draw.c:194
   **Bug Description:** In draw.c line 189, rb_append_char(&line_disp, '\0') is called unconditionally before syntax highlighting. If syntax highlighting fails and returns NULL, line 194 calls free(hl) on a NULL pointer (undefined behavior). Additionally, the null terminator is added before checking if highlighting is enabled.
   **Impact:** Potential crash when syntax highlighting fails or is unavailable. Undefined behavior from free(NULL) though most implementations handle it, still violates standard.

MEDIUM SEVERITY BUGS
====================

7. **Severity:** Medium
   **Location:** src/input.c:281-350 (escape sequence state machine)
   **Bug Description:** The escape sequence parser can get stuck in intermediate states if the terminal sends incomplete sequences (e.g., user presses ESC then types regular characters). The state machine only resets on valid complete sequences or when starting a new ESC sequence. Malformed input can leave it in esc_got_bracket, esc_got_1, etc. states.
   **Impact:** Editor becomes unresponsive to subsequent input until another valid escape sequence arrives. User experience degraded, requires typing ESC to reset state.

8. **Severity:** Medium
   **Location:** src/nodes.c:641-660 (pgb_move_to_pos)
   **Bug Description:** pgb_move_to_pos() moves cursor by calling pgb_move_right() in a loop for every position. For large documents or large cursor movements, this is O(n) and can be extremely slow. The function doesn't use the linked list structure efficiently - it could navigate directly to the target page.
   **Impact:** Poor performance on large files. Operations like Ctrl+A (select all) or search navigation become sluggish. User experience degraded on files >100KB.

9. **Severity:** Medium
   **Location:** src/syntax.c:164-186 (append_color), src/syntax.c:188-209 (append_text)
   **Bug Description:** The growable buffer helpers in syntax highlighting use INT_MAX as overflow check. If allocation fails, they free the buffer and set result to NULL. However, the initial capacity calculation (line_len * 4) can overflow for very long lines, and the realloc growth strategy doubles capacity which could also overflow.
   **Impact:** Potential integer overflow leading to incorrect buffer sizing or allocation failures. Long lines (>500MB of color codes) could cause issues, though unlikely in practice.

10. **Severity:** Medium
    **Location:** src/config.c:461-462 (config file path construction)
    **Bug Description:** snprintf is used to construct home config path, but if HOME environment variable is extremely long (>512 bytes), it could truncate. The check for overflow uses sizeof(home_rc) but doesn't verify the path fits before using it.
    **Impact:** Configuration file loading may fail silently if HOME path is too long. User settings not applied.

LOW SEVERITY / POTENTIAL RISKS
==============================

11. **Severity:** Low
    **Location:** src/term.cpp:209-227 (term_update)
    **Bug Description:** If terminal reports zero dimensions (ws_row=0 or ws_col=0), fallback to 24x80 is used. However, if the terminal is actually larger than 24x80 but temporarily reports zero, the editor will render incorrectly with truncated content until the next resize event.
    **Impact:** Temporary rendering glitch on terminal resize. User sees truncated content until window is resized again.

12. **Severity:** Low
    **Location:** src/nodes.c:217-236 (pgb_to_str)
    **Bug Description:** pgb_to_str() has a guard for NULL destination and zero size, but doesn't validate that the source paged_gap_buffer is in a consistent state (e.g., active_page not NULL, gap indices valid). If called on corrupted buffer, could read garbage.
    **Impact:** Potential crash or garbage output if buffer is corrupted. Defense in depth missing.

13. **Severity:** Low
    **Location:** src/render_buffer.cpp:29 (realloc usage)
    **Bug Description:** The render buffer uses realloc() which on failure returns NULL but leaves the original allocation intact. However, the code doesn't preserve the original pointer before realloc, so if realloc fails, the original data is lost (memory leak) and rb->data becomes NULL.
    **Impact:** Memory leak on allocation failure. Render buffer state corrupted. May cause rendering issues.

PERFORMANCE OPTIMIZATION RECOMMENDATIONS
========================================

1. **Optimize pgb_move_to_pos for O(1) page navigation:**
   Instead of moving character-by-character, calculate which page contains the target position by summing page content lengths, then move directly to that page. For large files, this reduces cursor movement from O(n) to O(log n) or O(1) for page navigation.

2. **Batch insert operations for file loading:**
   Modify file_read() to insert content in larger chunks (e.g., one page at a time) rather than character-by-character. This reduces the number of pgb_insert() calls from O(file_size) to O(file_size / PAGE_CAPACITY), significantly improving load time for large files.

3. **Add signal handler for graceful shutdown:**
   Install SIGINT (Ctrl+C) and SIGTERM handlers to perform cleanup (close files, restore terminal state, delete temp files) before exit. This prevents terminal corruption and temporary file pollution when user interrupts the editor.

SUMMARY
=======
Found 3 Critical bugs, 3 High severity bugs, 4 Medium severity bugs, and 3 Low severity risks.

Most critical issues involve:
- Memory capacity mismatches causing silent data loss
- Undo/redo system truncation causing data corruption  
- Missing signal handling for graceful shutdown

These issues should be addressed before production use, especially the memory capacity and undo/redo truncation bugs which directly impact data integrity.
